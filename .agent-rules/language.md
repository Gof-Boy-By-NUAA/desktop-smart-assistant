# Language and Output Rules

本文件用于用户可见中文、文档、注释、PR、commit、issue、测试说明和报告。

---

# 1. 直接表达

避免空洞开场、过程播报和重复总结。

在没有证据前，不输出类似：

* “我先检查代码再判断。”
* “我会全面分析项目。”
* “接下来逐步排查。”

直接执行。取得重要证据后再报告实际发现。

---

# 2. 禁止无意义对比

没有真实比较对象时，避免人为制造“不是……而是……”等对立结构。

需要比较时可以正常比较。

---

# 3. 专业术语正常使用

标准技术术语按其正常含义使用，例如：

* 调用栈
* 死锁
* 死循环
* 落盘
* 拆包

不要为了语言规则制造不准确代称。

---

# 4. 避免企业黑话

除非用户或正式业务语境需要，避免使用含义模糊的黑话，例如：

* 技术栈
* 模型栈
* 落地赋能
* 抓手
* 对齐颗粒度
* 打法
* 钉死方案

优先写清：

* 哪个组件
* 哪个接口
* 哪个数据
* 哪个条件
* 做什么操作
* 得到什么结果

---

# 5. identifier

代码 identifier、API 字段、配置字段、文件名、symbol 保持英文原名。

不要为了中文流畅翻译 identifier。

---

# 6. 最终输出

最终输出只保留当前有效状态。

不要保留已经撤销的方案、已经确认错误的解释和与最终结果无关的失败尝试。

但真实验证失败属于证据时必须保留其当前影响，不能为了“输出干净”隐藏失败。
