# Engineering Rules

本文件在修改代码、配置、构建文件或项目结构时读取。

---

# 1. 修改前读取当前内容

任何文件修改前读取当前版本。

文件可能被用户、其他 Agent、formatter、generator 或其他工具改变时，再次修改前重新读取相关区域。

---

# 2. 保护用户已有修改

不得用 Git 历史或旧副本覆盖用户当前工作区内容，除非用户明确要求恢复某个具体版本且风险范围明确。

禁止把以下操作当作普通修复手段：

* `git reset --hard`
* 未经授权改写共享历史
* 用历史版本整体覆盖当前文件
* 为方便处理而丢弃未提交改动

如果运行环境有更严格 Git Policy，服从环境限制。

---

# 3. 修改方式

优先使用能够产生清晰 diff 的文件编辑能力。

批量修改只有在以下条件同时满足时允许：

* 范围明确
* 匹配规则确定
* 不会误伤无关内容
* 修改后检查 diff
* 执行对应验证

不得通过大范围正则或脚本重写来掩盖无法理解的代码结构。

项目已有 generator、formatter、migration tool 可以按其正常职责运行。

---

# 4. 最小修改范围

只修改完成当前任务必须的内容。

不得顺手：

* 大范围 refactor
* 统一风格
* 清理无关 warning
* 更新无关依赖
* 改名无关 symbol
* 改写无关测试

除非它们直接阻止当前任务。

---

# 5. fast-fail

错误应在合适位置明确暴露。

不得为了继续运行而：

* 吞异常
* 返回伪造成功
* 隐藏失败
* 自动切换到用户没有要求的 fallback
* 用默认值掩盖必要数据缺失

确实属于产品要求的容错行为除外，但必须有明确规则和测试。

---

# 6. 依赖与格式解析

成熟 library 能可靠完成任务时，优先使用。

不得为了减少依赖数量手写复杂替代实现。

成熟文件格式优先使用可靠 parser；无法可靠解析时报告限制。

---

# 7. 临时文件

中间结果使用项目专用临时目录，并确保不会污染正式目录。

临时目录应进入 `.gitignore`。

任务结束后清理当前任务创建且确认所有权的无用临时资源。

涉及容器、端口、临时数据库或守护进程时读取 `.agent-rules/runtime.md`。

---

# 8. 修改后验证

任何代码、配置、构建修改都必须读取并执行 `.agent-rules/testing.md` 的适用规则。

不得仅因为编译通过就把行为修改判定为完成。
