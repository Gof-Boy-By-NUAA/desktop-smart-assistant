帮你把对话中产生的资料、灵感和零散笔记整理成结构化的本地知识库，自动维护索引和页面之间的交叉引用。

`knowledge-wiki` 使用 SmartAssistant 的受治理知识工具和 SQLite 事实源。工作空间中的 `knowledge/` 目录只是自动生成的只读视图，不是可写事实源。技能设置了 `always: true`，会**常驻上下文**，不需要任何外部依赖。

## 什么时候会触发

- 你分享了一篇文章、一份文档或一个 URL，想要沉淀下来
- 聊天过程中聊出了值得长期保留的结论
- 你想查一下之前积累过的知识

## 目录结构

```
knowledge/
├── index.md           # 自动生成的全局索引（只读）
├── log.md             # 自动生成的生命周期日志（只读）
└── <category>/        # 分类子目录（按内容自由分组）
    └── <slug>.md      # 知识页（文件名用小写加中划线）
```

## 三个核心操作

### 1. 收录（Ingest）

你分享了一段资料时，Agent 会：

1. 读懂原文，提取关键信息
2. 使用 `knowledge_search` 查找相关受治理文档并避免重复
3. 调用 `knowledge_write`，提供稳定的 `source_ref`、集合、作用域和敏感级别
4. 对用户有帮助时，保留返回的文档 ID 和不可变版本

### 2. 综合（Synthesize）

聊天中产生了新的结论或洞见时：

1. 使用 `knowledge_search` 查找已有的受治理文档
2. 使用 `knowledge_write` 创建文档或生成新版本
3. 在正文和 `source_ref` 中保留来源声明

### 3. 查询（Query）

你问到以前积累的知识时：

1. 使用 `knowledge_search` 检索
2. 基于返回的引文和完整 Citation v3 URI 回答
3. 需要更多上下文时，把该 URI 交给 `knowledge_get`
4. 逐字保留 URI，禁止截断、调整参数顺序或手工重建；拒绝时重新检索

## 知识页怎么写

```markdown
# 页面标题

> Source: <来源 URL 或简要说明>

正文内容。页面之间用相对路径链接：
[相关页](../category/related-page.md)

## 要点

- ...

## 相关页面

- [页面 A](../category/page-a.md) — 为什么相关
```

<Note>
- `> Source:` 用来记录这条知识的来源。有明确来源时一定要写
- 交叉引用很重要：创建或更新某页时，记得也去关联页面里补上反向链接
- **只链接已经存在的页面**。如果某个概念值得单独成页，先建好再加链接
</Note>

## 自动生成的索引

`knowledge/index.md` 是自动生成的兼容投影，当前展示格式为按分类分组的扁平列表：

```markdown
# Knowledge Index

## 分类 A
- [页面标题](category-a/page-slug.md) — 一句话摘要

## 分类 B
- [页面标题](category-b/page-slug.md) — 一句话摘要
```

禁止直接编辑该文件。分类名称和组织方式由受治理写入操作生成。

## 自动生成的日志

`knowledge/log.md` 同样由生命周期记录生成：

```markdown
## [YYYY-MM-DD] ingest | 页面标题
## [YYYY-MM-DD] synthesize | 页面标题
```

## 写作约定

- **文件名**用小写加中划线，比如 `machine-learning.md`
- **一页只讲一件事**，需要关联的内容通过链接串起来
- **有了就更新，不要重复建页**
- **禁止直接修改投影**，创建、回滚和移除分别使用 `knowledge_write`、`knowledge_rollback`、`knowledge_revoke`
- **写精华别抄全文**，抓住要点就行
- **基于知识回答时使用完整 Citation v3 URI**，逐字保留所有参数
- **把 `source_ref` 视为来源声明**；其哈希证明声明未变，不证明外部来源真实
