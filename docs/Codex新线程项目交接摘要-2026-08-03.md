# SmartAssistant 新线程项目交接摘要（2026-08-03）

## 项目目标

完成 SmartAssistant 桌面端、Web 端和多通道 Agent 的真实可交付闭环。改进模块必须以固定协议和数据集达到或超过 SmartAssistant 基线；最终必须通过目标客户受控环境的真实测试与签署验收。

本地测试、同仓 verifier、local Git commit 都不能替代生产、外部独立验证、签名制品或客户验收。

## 当前实现情况

- 当前 local HEAD：afb7cddb95bb8523d2dd5314f5c2bb6fc088f637，提交说明为 fix: persist scheduler execution claims fail closed。
- CMRC2018 本地全量 3219 query 比较仍显示检索改进优于基线：Recall@1 由 0.1121466 到 0.8984157，MRR@10 由 0.1209530 到 0.9183986，平均延迟由 2.2025 到 1.2086 ms。
- Web 文件、目录预览、SSE 与日志 URL 已移除 first-party bearer query，并增加 owner/epoch/revocation 约束。
- SSE 有 SQLite durable prefix journal；重启仅回放已持久化前缀，非终态只报告 unconfirmed，绝不伪称 worker 继续运行。
- Scheduler 新增 SQLite WAL/FULL durable execution ledger。每次 scheduled/manual 副作用在 callback 前写入 running claim；成功先写账本、后推进 JSON 排程；异常为 in_doubt 并禁止自动重试。
- Scheduler execution key 包含服务端生成的 task generation，防止删除后重建同一 task id 和 due time 被旧成功记录污染。
- Web/桌面“立即执行”强制 idempotency_key，只有当前 service 仍追踪到的同一 worker 可返回 already_queued。重启或中断的 running claim 被拒绝为不确定执行，UI 显示风险。

## 操作约束

- 使用 apply_patch 修改文件；不要把 generated manifest 或报告字段手工改为 PASS/YES。
- release-evidence-manifest.json 是 Git-ignore 的生成制品。生成后 git status --short 应为空；CLI 必须拒绝写入 Git-tracked output。
- Git 会显示全局 ignore 权限 warning。只在 git status --short 为空时认为工作区干净。
- 建议新线程先执行：git status --short、git log -1 --oneline，然后阅读本文件、调度审查补充和严格多角色审查报告。
