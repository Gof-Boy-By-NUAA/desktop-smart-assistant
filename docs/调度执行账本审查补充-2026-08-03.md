# SmartAssistant 调度执行账本审查补充（2026-08-03）

## 审查范围与当前结论

本补充审查当前 F1-002 的 Scheduler 执行链，攻击「不该成功却返回成功」和「崩溃后重复副作用」。

本轮本地代码已增加 tasks.json.executions.sqlite3 持久化执行账本，但这不是生产或客户验收证据。五个角色仍全部保留 VETO；客户、受保护远程 CI、签名制品、部署/回滚、72 小时长稳和告警证据仍然缺失。

## 第一轮独立发现

### FDE 产品交付官

| 严重度 | 文件位置 | 问题与结论 | 推荐方案 |
| --- | --- | --- | --- |
| P0（已局部修复） | SchedulerRunHandler、TasksPage、console.js | 原「立即执行」只返回 queued。网络断开、进程退出或重复点击时员工无法判断任务是否执行。现在 Web/桌面端发送 idempotency_key；服务端只在当前 worker 已知存活时返回 already_queued；跨重启或中断则拒绝并显示 running/in_doubt。 | 保留强制 idempotency key；生产前增加经过授权的人工复核/处置流程与审计 UI。 |
| P1（未关闭） | TaskStore.record_scheduled_execution_uncertain | in_doubt 对用户可见且阻止自动重试，但没有受控的人工处置工作流。用户只能停用、删除或新建任务，无法在同一审计链内确认已送达/未送达。 | 增加 owner-bound、双确认、可审计的处置命令；不得把处置默认解释为未执行。 |

### 执行可靠性架构师

| 严重度 | 文件位置 | 问题与结论 | 推荐方案 |
| --- | --- | --- | --- |
| P0（已局部修复） | TaskStore.claim_scheduled_execution、SchedulerService._check_and_execute_tasks | 旧实现只用进程内 set 防重，两个实例或重启会同时执行同一任务。现在以 SQLite WAL/FULL、BEGIN IMMEDIATE、任务代次加触发时刻作为 occurrence key，并在外部回调前持久化 running。 | 不自动过期 running claim；未知副作用不得以 TTL 回收。 |
| P0（已局部修复） | TaskStore.finish_execution、TaskStore.advance_scheduled_execution | 外部副作用成功但 JSON 排程推进前崩溃，旧实现会重复执行。现在先标 succeeded，以后扫描只推进排程、不重放 callback。 | 所有其他工具副作用也要采用 durable outbox/claim 协议。 |
| P1（未关闭） | SchedulerService._execute_task | 回调 bool 的 False 和异常都可能发生在外部服务已接受消息之后。当前实现 fail-closed 为 in_doubt，避免重复；不能证明 exactly-once。 | 每个外部通道提供幂等投递标识/送达查询，或明确限制为 at-most-once 加人工处置。 |

## 第二轮交叉攻击与裁决

| 争议点 | 交叉攻击证据 | 最终裁决 |
| --- | --- | --- |
| SQLite 唯一索引是否等于 exactly-once | 可靠性角色指出外部 send 在网络异常后状态不可知；测试破坏角色以 False/异常路径验证自动重试会导致重复。 | 不接受 exactly-once 声明。采用 durable at-most-once claim、in_doubt 可见化和禁止自动重试。 |
| running 是否可显示为 queued | 重启后的 ledger row 无法证明 worker 仍在运行；SystemExit 和新 service instance 可复现。 | 仅本进程且本地执行集合中仍活跃的同 key 可返回 already_queued；其他一律拒绝为不确定执行。 |
| 删除/重建同 ID 是否可沿用旧成功记录 | 红队构造相同 id、相同 due timestamp 的重建任务。 | 拒绝仅 task_id/due_at 键；采用不可编辑 task generation。 |
| 本地 security report 是否关闭发布 VETO | report 只在本地重放，同 PR 可改 verifier。 | report 只支持本地实现事实；不得支持生产、独立验证或客户验收声明。 |

## 最终决策登记

| 角色 | 结论 | 可验证的阻断条件 |
| --- | --- | --- |
| FDE 产品交付官 | VETO | in_doubt 的受控人工处置与真实目标客户用户旅程验收尚未完成。 |
| 执行可靠性架构师 | VETO | 工具/worker/外部投递没有端到端可证明幂等协议；真实崩溃、恢复和多实例演练未完成。 |
| 治理与红队审计官 | VETO | protected remote、独立 verifier、签名制品和不可伪造证据链不存在。 |
| 测试破坏官 | VETO | 未对真实代理/通道/磁盘指令边界做生成式或故障注入攻击。 |
| 运维与部署审计官 | VETO | Docker/installer、迁移回滚、72H soak、告警 fire 和生产配置验证均未运行。 |

被拒绝的方案：把 SQLite 唯一索引、单元测试、同仓 verifier、局部 benchmark 或本地 commit 中任意一个单独称为 exactly-once、生产就绪或客户验收通过。
