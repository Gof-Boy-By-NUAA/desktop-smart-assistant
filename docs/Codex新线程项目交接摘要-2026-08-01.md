## 1. 项目目标

在原始 SmartAssistant 基础上完成一套可审计、可恢复、可验证的桌面/多通道 Agent 产品，并满足以下最终边界：

1. 整体能力和性能至少与原始 SmartAssistant 持平。
2. 已改进模块必须以正式、可复算的基准证明性能或安全性超过原实现。
3. 最终必须通过目标客户在其受控环境中的真实测试，不能以模拟、占位、N/A 或本地脚本代替。
4. 必须进行五角色、三轮次的严格审查，目标不是证明方案正确，而是持续寻找漏洞、绕过路径和假成功。
5. 所有报告必须与当前实现、固定数据集、Git 提交、CI 运行和部署制品形成可追溯证据链；证据缺失时保持 `NO`、`ABSENT` 或 `NOT_RUN`。

#### B. Web 鉴权主体、注销与重启失效

- Bearer token 升级为 v2：版本、时间戳、主体、nonce、完整 HMAC。
- 引入持久签名 subject token，用于密码重新登录后保持同一会话所有者；subject token 本身不能作为认证凭据。

- 默认绑定强制回环地址；即使设置密码也不再自动扩大到 `0.0.0.0`；显式公网绑定但无密码时回退到 `127.0.0.1`。

## 7. 新任务必须知道的上下文和约束

1. **不要信任旧报告中的 `passed=true`。** 必须检查实现指纹、数据 SHA、独立 verifier、新鲜度和 commit 绑定。
2. **不要把本地测试等同生产证据。** Web 报告当前只证明本地攻击集通过。
3. **不要把 session_id 当身份。** Web 的可信主体只能来自 `_require_auth()` 及服务端创建的 context。
4. **subject token 不是认证令牌。** 它只用于密码登录后保持设备主体连续性。
5. **删除会话必须保留墓碑语义。** 不得改回物理删除后允许迟到写入复活。
6. **citation session identity 不由客户端声明。** 必须使用服务端能力绑定。
7. **不要弱化失败关闭。** migration、密钥读取、HMAC 长度、所有者检查和 verifier 复算失败都必须阻断。
8. **Skills blocked 是真实状态。** 缺 provenance 时只能保持 `blocked_invalid_dataset`。
9. **客户验收必须外部真实执行。** 缺输入或签名时保持 pending。
10. **整个 SmartAssistant 当前未被 Git 跟踪。** 这是 release P0，不是文档问题。
11. **用户已允许启用新任务/子代理。** 可并行委派互不重叠的工作，但编码代理必须有不重叠写入范围，并由主任务复核集成。
12. **用户要求持续执行直到完整项目完成。** 但不得通过伪造证据、修改 PASS 字段或忽略外部阻断来宣称完成。
