# 屏幕录制沉淀 Skill 技术方案（2026-08-20）

> 状态：评审通过（5 项未决问题已拍板，见第 9 节），可按 M1 实施。
> 关联：《未完成项与路线图-2026-08-20.md》#6；v2.0 方案 Phase 2。

## 1. 目标与范围

**一句话**：用户在桌面端录一段操作屏幕的视频，系统用视觉模型把操作过程分析成步骤序列，自动生成一个可审阅、可安装、可复用的 Skill 包。

**MVP 范围（M1）**：
- 手动开始/停止录屏（桌面端按钮，非定时）
- 抽帧 + 视觉模型分析 → 结构化步骤序列
- 生成 Skill 草稿（SKILL.md + scripts/ 骨架），**必须经人工审阅确认后才安装**
- 安装后进入现有技能体系（可见、可启用/禁用、可被检索命中）

**明确不做（M1 阶段）**：定时录屏、自动安装免审阅、回放自验证、Computer Use 执行（属路线图 #7，本方案只为其预留步骤 IR 格式）。

## 2. 现状勘察结论（代码实证）

| 事实 | 位置 |
|---|---|
| 技能包 = 目录 + SKILL.md（YAML frontmatter：name/description/metadata.smart_assistant.requires/install/os）+ scripts/ | `skills/image-generation/` |
| 已有"教 agent 写技能"的技能，蒸馏产物应遵循同一规范 | `skills/skill-creator/SKILL.md` |
| 技能可编程注册入口 | `agent/skills/service.py:159 add(payload)` |

## 3. 总体架构

```
[桌面端 ScreenRecorder 面板]
   │ ① desktopCapturer 录屏(webm) + 录制元数据
   ▼
[后端 recording 存储区]  workspace/recordings/<id>/  (owner 隔离)
   │ ② 抽帧(ffmpeg 缺省，纯 Python 兜底: 定时截图序列 mss)
   ▼
[agent/tools/screen_analyzer.py]  视觉模型路由(国内 VL 优先)
   │ ③ 帧序列+时间戳 → 步骤 IR(JSON)
   ▼
[skill 蒸馏器 agent/skills/distiller.py]
   │ ④ 步骤 IR → SKILL.md + scripts/ 草稿(遵循 skill-creator 规范)
   ▼
[桌面端 审阅视图(SkillsPage 扩展)]  人工确认/编辑/拒绝
   │ ⑤ 确认 → service.add() 安装
   ▼
[技能体系]  可检索/可启用/可执行
```

**关键设计决策**：
1. **录屏在 Electron 侧**（desktopCapturer/MediaRecorder），不在 Python 侧——Windows 权限模型简单、无新依赖、可录系统音频提示；Python 兜底方案（mss 定时截图）仅用于无 Electron 环境，M1 不实现。
2. **分析产物是"步骤 IR"中间表示**（JSON），不直接生成代码——IR 可被人工审阅、可被 M3 回放验证复用、可被 #7（Computer Use）作为执行脚本来源。
3. **生成的是"技能草稿"而非"已安装技能"**——人工审阅是治理硬要求（防录屏内容含敏感信息直接进技能库、防模型幻觉生成错误流程直接生效）。
4. **复用现有安装路径** `service.add()`，不发明第二条安装通道（单一通道=单一审计点）。

## 4. 模块设计

### 4.1 ScreenRecorder（桌面端，新增）
- `desktop/src/renderer/src/components/ScreenRecorder.tsx`：录制按钮、 elapsed 计时、停止、提交分析。
- `desktop/src/main/`：新增 IPC `screen-recorder-start`（desktopCapturer.getSources → 返回源列表，默认主屏）、`screen-recorder-save`（接收 webm 二进制块，写入后端上传）。
- 上传：分片 POST 到后端新路由 `POST /api/recordings`（复用 desktop-backend-request 通道，鉴权沿用现有 bearer/设备身份）。
- 录制元数据：{id, owner_id, started_at, stopped_at, source, fps, size_bytes, sha256} 随末片提交。
- **权限兜底（评审拍板）**：捕获 `desktopCapturer.getSources()` 错误，弹出清晰引导文案（"隐私与安全 → 屏幕录制 → 允许 Smart Assistant"）+ 一键重试；失败 fail-closed，不引入 Python 兜底录屏方案。
- **性能仪表盘（评审拍板）**：录制中实时显示 CPU/内存/磁盘占用；低配机（Win10 8GB 档）自动警告并建议降低 FPS。

### 4.2 录屏存储区（后端）
- 路径：`workspace/recordings/<recording_id>/`（video.webm + meta.json + frames/ + analysis.json + draft/）。
- **路径安全**：写入必须过 `common/path_safety` 与治理路径判定；recordings 目录视为用户私有数据，纳入 owner 隔离（同会话归属）。
- **保留策略**：M1 手动删除（审阅视图提供"删除录制"）；保留期与自动清理策略 M2 再定（需评审）。

### 4.3 screen_analyzer 工具（后端，新增 `agent/tools/screen_analyzer.py`）
- 输入：recording_id + 分析选项（抽帧间隔、最大帧数、模型偏好）。
- 抽帧（评审拍板）：**默认纯 Python 实现**（mss / PIL / OpenCV 纯 Python 路径，零新增系统依赖）；ffmpeg 为**可选高级选项**（设置中勾选"使用 ffmpeg 加速抽帧"，用户自行安装，未安装则自动降级纯 Python）。抽帧优先级：纯 Python > ffmpeg。策略：默认每 2 秒 1 帧 + 画面变化检测（感知哈希差值 > 阈值补帧），上限 60 帧（控 token 成本）。
- 模型路由：`agent/tools/utils/` 新增 `vision_router.py`——按优先级 [用户显式指定 > DASHSCOPE(Qwen-VL) > doubao(VL) > deepseek(VL) > gemini(用户显式选择时才用国外)] 选定 bot，调用现有 bot_factory 创建实例；无可用 key 时 fail-closed 报"未配置视觉模型"。
- 输出：步骤 IR `analysis.json`：
```json
{
  "schema_version": 1,
  "recording_id": "...",
  "model_used": "qwen-vl-max",
  "steps": [
    {"index": 1, "timestamp_s": 3.5, "action": "click|type|drag|hotkey|wait",
     "target_description": "Excel 工具栏'保存'按钮", "region": [x,y,w,h],
     "text": null, "confidence": 0.86}
  ],
  "summary": "在 Excel 中整理销售表并保存为 xlsx",
  "suggested_skill_name": "excel-sales-cleanup",
  "warnings": ["第 4 步画面模糊，置信度低"]
}
```
- **成本护栏**：单帧图像送模型前缩放到 ≤1280px 宽；总帧数硬上限；分析超时 180s fail-closed。

### 4.4 Skill 蒸馏器（后端，新增 `agent/skills/distiller.py`）
- 输入：analysis.json（步骤 IR）+ 用户可选命名/描述覆盖。
- 生成：
  - `SKILL.md`：frontmatter（name 取自 suggested_skill_name 经 slug 校验、description 取自 summary、metadata.smart_assistant.os=["windows"]）+ 正文（步骤列表、注意事项、置信度低的步骤标注"需人工复核"）。
  - `scripts/`：M1 只生成 `steps.json`（IR 原样归档）+ `README.md`（说明此技能由录屏蒸馏生成、如何人工完善）；**不生成可执行代码**（M3 才考虑，且需单独评审——模型生成代码直接可执行是红队不可接受面）。
- 命名冲突：与现有技能同名时 fail-closed 提示改名，不覆盖。

### 4.5 审阅视图（桌面端 SkillsPage 扩展）
- 新路由：`GET /api/recordings`（列表）、`GET /api/recordings/<id>/analysis`（IR）、`POST /api/recordings/<id>/distill`（生成草稿）、`POST /api/recordings/<id>/install`（确认安装）、`DELETE /api/recordings/<id>`。
- UI：录制列表 → 分析结果（步骤时间线 + 视频联动定位 + **"确认步骤"模式**：人工逐步确认/修正 IR，评审拍板）→ 草稿预览（SKILL.md 渲染 + 可编辑名称/描述）→ [确认安装] [拒绝并删除]。
- 安装动作调用 `service.add()`；拒绝则物理删除录制目录。

## 5. 模型路由与合规

- 默认优先级：Qwen-VL（dashscope）→ 豆包 VL → DeepSeek-VL；**国外视觉模型（Gemini 等）仅在用户于设置中显式勾选"允许国外视觉模型"时进入候选**（对应 v2.0 Phase 0 的合规提醒机制，本方案依赖该机制落地，若 Phase 0 未做则 M1 硬编码仅国内候选）。
- 每次分析在 analysis.json 记录 `model_used`，审阅视图展示——"哪个模型看了我的屏幕"必须可见。

## 6. 安全与治理（红线）

1. **明示同意**：录屏按钮第一击必须弹出说明（录制范围、数据去向、模型名称），用户确认才开始；录制中状态栏常驻显眼指示。
2. **隐私**：屏幕内容可能含密码/私聊/机密——M1 策略：①分析仅发往用户已配置 key 的模型商；②审阅视图提供"丢弃"一键物理删除；③SKILL.md 生成时过滤 IR 中 `text` 字段的疑似敏感值（密码框、身份证/银行卡模式正则），命中即替换为 `<redacted>` 并在 warnings 标注。
3. **路径与权限**：全部写入限 `workspace/recordings/` 与技能目录，过 `common/path_safety`；录制与技能归属会话 owner，跨 owner 不可见（沿用现有 owner 隔离门禁）。
4. **不生成可执行代码**（M1/M2）：蒸馏产物是文档型技能；可执行脚本化属 M3，需单独红队评审。
5. **证据链联动**：本方案触及 `agent/tools/`、`agent/skills/`、`channel/web/`、`desktop/src`——均在 web 边界/技能门禁的源码指纹集合内。**实施完成后必须重生成对应证据报告**（生成器已确定性 LF，Windows 可直接重生成），否则 CI 按设计 fail-closed。
6. **审计**：录屏创建/分析/蒸馏/安装/删除全部写入执行账本（沿用 AgentBridge 账本模式），可回溯。

## 7. 分阶段实施

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1（本方案主体） | 手动录屏→上传→抽帧→VL 分析→IR→草稿→审阅→安装 | 端到端手工验收 + 单测覆盖 IR/蒸馏/路由；**≥80% 分析样本人工复核确认 IR 可直接落地（评审拍板）**；**低配场景实测（Win10 8GB+SSD，录屏额外负载 <5%，评审拍板）** |
| M2 | 定时录屏、保留策略、批量草稿 | 评审后另立方案 |
| M3 | 回放自验证、可执行脚本化（对接 #7 Computer Use） | 独立红队评审后另立方案 |

## 8. 测试与证据策略

- 单测：抽帧策略（帧上限/变化检测）、IR schema 校验、蒸馏输出符合 skill-creator 规范（frontmatter 解析往返）、命名冲突 fail-closed、敏感信息过滤（正例/反例）、vision_router 优先级与无 key fail-closed。
- 属性测试：任意 IR 输入蒸馏产物必须 frontmatter 可解析且 name 合法 slug。
- 集成：伪造 VL bot（桩）跑通 录制→分析→草稿→安装 全链路（CI 无真实模型 key，桩注入）。
- 证据：实施完成后重生成 web 边界 + 技能相关证据；新功能性能声明（如"分析耗时"）须附新证据，不外推。
- 成本与日志（评审拍板）：单次分析 ≤60 帧（≈90k token）硬上限 + 帧压缩 + 180s 超时，超限 fail-closed（文案"分析成本已达上限，请减少操作次数或使用手动步骤"）；每次分析的帧数/token 估算/耗时写入执行账本，作为 M2 用户配额动态调整依据。

## 9. 评审拍板记录（2026-08-20，已结案）

五个未决问题经评审全部拍板，实施严格遵循：

1. **录屏权限**：主路径 `desktopCapturer`（零新增 Python 依赖）。企业策略拦截时 fail-closed + 引导文案（"隐私与安全 → 屏幕录制 → 允许 Smart Assistant"）+ 一键重试。M1 不做 Python 兜底录屏。
2. **VL 准确率**：灰度度量，不预设硬数字。M1 验收：≥80% 分析样本人工复核确认"IR 可直接用于 Skill 落地"；低于阈值触发人工干预（IR 页"确认步骤"模式）。模型幻觉由审阅流程兜底。
3. **token 成本**：维持 ≤60 帧（≈90k token）+ 帧压缩 + 180s 超时，不收紧。超限 fail-closed 并给文案。成本监控写执行账本，供 M2 配额调整。
4. **ffmpeg**：默认纯 Python 抽帧（mss/PIL/OpenCV 纯 Python 路径）；ffmpeg 为可选高级选项（设置勾选、用户自装、未装自动降级）。M1 不强制引入；实施后验证画质性能差异再定默认。
5. **录制性能**：M1 接受低配机影响（Win10 8GB+SSD 为基线）。UI 内置实时性能仪表盘（CPU/内存/磁盘），低配自动警告并建议降 FPS。验收含低配实测，目标额外负载 <5%；超标则 M2 引入性能模式。
