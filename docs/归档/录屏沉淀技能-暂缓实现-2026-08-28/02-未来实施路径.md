# 录屏沉淀技能未来实施计划

> **封存约束：** 本计划只在用户明确解除 `FROZEN_NOT_IMPLEMENTED` 后执行。启封后，执行者必须使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans` 按任务推进；当前不得据此改代码。

**目标：** 在不降低 SmartAssistant 现有能力的前提下，实现可审计、可恢复、隐私失败关闭的录屏→Skill 全链路，并取得同一签名制品上的性能、部署和客户证据。

**架构：** Electron 负责录制与同步 PNG 采样；Python 服务负责 owner-scoped 上传、状态机、视觉分析、确定性蒸馏和审批安装。状态、内容哈希、审计和制品身份贯穿全链路，外部受保护验证器负责发布放行。

**技术栈：** Electron/React/TypeScript、Python、SQLite 事务账本、Web API、MediaRecorder、国内视觉模型 provider、SHA-256、PyInstaller/electron-builder、受保护 CI。

**规范：** `docs/归档/录屏沉淀技能-暂缓实现-2026-08-28/01-技术方案冻结版.md`

## 全局约束

- M1 不生成可执行脚本，不提供免审自动安装。
- owner 只能由服务端认证上下文解析。
- 默认采样路径固定为 Electron 录制期间输出 PNG；ffmpeg 仅为显式高级重抽工具。
- TTL 7 天属于 M1。
- 未经重新五角色三轮审查，不得进入 F1-003。
- 所有本地验证仅是开发证据，不能解除客户、签名制品、72 小时或生产告警硬否认。
