# 录屏沉淀技能技术方案冻结版

## 1. 状态与目标

本文是未来启封时的单一推荐方案。当前状态为 `FROZEN_NOT_IMPLEMENTED`，本文不授权实现，也不证明已有代码满足方案。

目标：员工在桌面端明确同意后录制一段操作，系统在本地生成视频与采样帧，经受控视觉模型生成可追溯步骤 IR，再产生不可执行的 Skill 草稿。草稿必须经服务端强制人工审批，审批内容与最终安装内容完全同哈希，安装后在技能列表可核验。

M1 明确不做：定时录屏、免审自动安装、可执行脚本生成、Computer Use 回放、后台隐式录制、自动将原始画面长期写入 Skill 包。

## 2. 冻结后的唯一技术选择

### 2.1 录制与抽帧

- 主路径固定为 Electron `desktopCapturer` + `MediaRecorder` 录制 WebM。
- 渲染进程在录制期间每 2 秒把当前帧绘制到 canvas，输出有单调时间戳和连续采样序号的 PNG。
- PNG 是 M1 默认分析输入；后端不依赖 Pillow、mss 或 OpenCV 解码 WebM。
- ffmpeg 只允许作为用户显式启用的“从存档视频重新抽帧”高级工具；缺失时不得影响 M1 主路径。
- 原方案第 9 节“默认 Python 抽帧”作废，避免与主架构冲突。

### 2.2 保留策略

- TTL 属于 M1 的隐私与磁盘安全边界，不延后到 M2。
- 未完成审阅的 recording 默认保留 7 天；用户可每次显式延长 7 天，动作必须留审计记录。
- 安装 Skill 后，原视频和帧仍受 TTL 约束；Skill 包只保存脱敏、白名单化的 IR 和文档。
- M2 只考虑定时录制、批量草稿和策略化配额，不重新定义 M1 的基础 TTL。

### 2.3 数据出境与明示同意

- 开始录制前必须展示捕获屏幕、实际 provider、模型、数据目的地、保留期限和停止方法。
- 同意凭证绑定 `owner_id + recording_id + provider_id + model_id + data_destination + policy_version`；实际调用任一字段变化时重新征得同意。
- 上传给模型前，在本地执行窗口/区域排除和敏感区域遮挡。密码管理器、安全桌面或企业禁录窗口无法可靠遮挡时，录制或分析必须失败关闭。
- 自动路由仅限经合同允许的国内候选；显式指定 provider 不可用时失败，不静默回退到其他数据目的地。

## 3. 组件边界

| 组件 | 单一责任 | 主要输出 |
|---|---|---|
| Desktop ScreenRecorder | 明示同意、选择屏幕、录制、PNG 采样、性能显示、取消 | WebM、PNG、客户端采样元数据 |
| Recording API | 身份解析、分片去重、配额、finalize、TTL、墓碑 | owner-scoped recording 与持久状态 |
| Screen Analyzer | 本地遮挡、provider 路由、VL 调用、严格 IR 生成 | `analysis.json` 与调用收据 |
| Skill Distiller | 严格 IR 校验、递归脱敏、确定性草稿 | canonical draft bytes 与 SHA-256 |
| Approval Service | 审批、撤销、过期、CAS 安装门禁 | 绑定草稿哈希的审批凭证 |
| Review UI | 视频/帧联动、步骤修正、数据去向、错误和恢复状态 | 用户可验证的审批动作 |
| Evidence/Release | 外部验证、制品绑定、性能与客户证据 | 签名收据、SBOM、provenance |

## 4. 服务端状态机

每个实体以 `(owner_id, recording_id, attempt_id)` 唯一定位。服务端至少持久化：

```text
CREATED
  -> UPLOADING
  -> UPLOADED
  -> ANALYZING
  -> ANALYZED
  -> DRAFT_READY
  -> APPROVED
  -> INSTALLING
  -> INSTALLED
```

终止或旁路状态：`FAILED`、`IN_DOUBT`、`REJECTED`、`DELETED`、`EXPIRED`。

规则：

- 所有转换使用数据库事务和 compare-and-set 版本号；客户端不能提交 owner 或目标状态。
- 每个副作用操作必须带持久幂等键，同一键重试返回同一收据，不重复调用 provider 或安装技能。
- 删除和过期写入墓碑；旧 attempt、迟到 finalize、迟到 analyzer 结果和旧审批不得复活对象。
- `IN_DOUBT` 只能通过带审计收据的人工/自动处置转换，不能按普通重试再次执行外部副作用。
- 审批、撤销、编辑和安装并发时，以服务端 canonical draft hash 和状态版本进行 CAS；失败返回 409，不返回假成功。

## 5. 上传与持久化合同

1. `POST /api/recordings` 创建上传会话，由认证上下文解析 owner。
2. `PUT /api/recordings/{id}/chunks/{index}` 携带 offset、长度、chunk SHA-256 和幂等键；同索引同内容重复返回原收据，不同内容返回 409。
3. `POST /api/recordings/{id}/finalize` 校验总长度、全文件 SHA-256、WebM 容器、PNG 清单、配额和状态版本。
4. 服务端只写固定的 owner-scoped 根目录，逐级拒绝绝对路径、UNC、设备路径、symlink、junction 和 reparse point。
5. 数据先写同卷 staging；完整写入、文件 fsync、目录 fsync 和校验后原子 rename，并创建 READY 标记。崩溃恢复只能看到旧完整版本或新完整版本。

服务端限额：单次录制不超过 10 分钟、归档不超过 200 MiB、每 owner 默认 2 GiB、每 owner 同时一个上传会话；超限立即返回 413/429，不继续写入。

## 6. IR 合同

IR 使用严格版本化 allowlist，不接受未知字段。必需字段：

```json
{
  "schema_version": 1,
  "recording_id": "rec-...",
  "attempt_id": "attempt-...",
  "provider_id": "dashscope",
  "model_used": "qwen-vl-max",
  "data_destination": "阿里云百炼（国内）",
  "frame_width": 1280,
  "frame_height": 720,
  "coordinate_space": "frame_pixels_top_left",
  "display_id": "screen-1",
  "sampling_interval_ms": 2000,
  "sampling_gaps": [],
  "steps": [],
  "summary": "...",
  "suggested_skill_name": "...",
  "warnings": []
}
```

每个 step 必须满足：`index` 从 1 唯一递增；`timestamp_s` 有限且单调；`frame_index` 指向真实 PNG；稀疏帧必须由 `sampling_gaps` 解释；region 四个值有限、宽高为正且不越过帧边界；action 属于冻结枚举。

所有 JSON 序列化禁用 NaN/Infinity。任何缺失、重复、乱序、越界、无效引用、伪造 provider/destination 或未知字段在产生草稿前失败关闭。

## 7. 确定性草稿、脱敏与审批

- 只把白名单字段写入 Skill 包；所有用户/模型可控字符串先递归脱敏，再参与渲染。
- `summary`、`target_description`、`warnings`、嵌套值、错误消息和日志都属于脱敏范围，不能只处理 `step.text`。
- `created_at` 由服务端首次持久化时生成，只写账本元数据；同幂等键重试复用，不让当前时间改变 canonical draft bytes。
- canonical draft 包含确定顺序、UTF-8、LF、固定 JSON 格式的 `SKILL.md`、`scripts/steps.json`、`scripts/README.md`；以完整字节清单计算 SHA-256。
- 审批凭证绑定 owner、recording、attempt、draft SHA-256、IR SHA-256、schema/policy version、approved_at 和过期时间。
- 编辑、重蒸馏、撤销、策略升级或过期都会使凭证失效；安装只接受与审批完全同哈希的 staging 目录。
- M1 Skill 包不含可执行代码。安装后只是受治理的文档型技能，不能声明具备自动回放能力。

## 8. 产品旅程与错误状态

桌面端必须提供：选择屏幕与明示同意、录制常驻指示、暂停/停止、上传进度、取消、分析进度、帧与视频联动、步骤编辑、数据去向、草稿预览、审批、安装、拒绝删除、历史恢复和最终技能列表核验。

所有界面区分：`loading`、`success`、`failure`、`retryable`、`cancel_requested`、`cancelled`、`timeout`、`in_doubt`。断线或服务重启后通过服务端状态恢复，不能把空列表、无响应或本地缓存当作成功。

## 9. 性能、证据与发布边界

- 现有 SmartAssistant 能力采用同硬件、同数据、同负载配对比较，候选必须非劣。
- 每个声明改进模块预注册指标、方向、样本量、排除规则和置信区间；只有配对原始样本证明严格超越时才能声明提升。
- 录屏 M1 单独预注册分层任务集、人工判定规则和盲审流程；IR 可直接落地率门槛为不低于 80%，但必须同时报告样本量、分层和置信区间。
- Win10、8 GiB RAM、SSD 实机测量录制额外 CPU/内存/磁盘负载，目标额外 CPU 负载小于 5%；测量窗口、采样频率和基线必须冻结。
- 发布采用外部受保护 verifier、独立 clean checkout、逐 blob 绑定、固定 Actions/依赖/镜像/工具、build once、SBOM、provenance 和签名制品。
- 安装、迁移、回滚、72 小时 soak、告警和客户验收必须消费同一 artifact SHA；仓库内测试、桩、同仓 verifier 或旧报告不能替代这些证据。
