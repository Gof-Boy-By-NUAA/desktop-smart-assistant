## 第二轮：交叉反驳与唯一裁决

### 争议 1：最终发布必须以 `e475a6b` 为祖先吗

- 运维第一轮提出祖先条件，FDE 反驳：产品和证据合同要求绑定实际发布提交，不要求保留特定历史拓扑；cherry-pick、squash 或安全重写均可能产生等价实现。
- 治理确认：不能复用 `e475a6b` 的局部证据证明重写后的完整实现。
- **最终裁决：** 不要求祖先关系。最终提交 R 必须包含经独立复核的等价完整实现，所有测试、源码指纹、制品、SBOM、provenance、客户和生产证据重新绑定 R。
- **拒绝方案：** 直接发布 `e475a6b`；或客户证据指向旧提交而制品来自另一个提交。

### 争议 2：敏感字段泄漏是 P0 还是 P1

- 测试破坏官初判 P0；FDE、可靠性和运维反驳：当前切片只生成未安装草稿，尚未证明跨 owner 或公开暴露，直接定生产 P0 过度。
- 运维补充：脱敏发生在 VL 调用后，无法撤回已经外发的原始像素，这是方案遗漏。
- **最终裁决：** 当前原型的产物泄漏为 P1 且阻断接入；一旦跨 owner、公开、自动安装、外发未授权 provider 或不可逆暴露，升级 P0。唯一方案是外发前本地遮挡 + 严格 allowlist + 全产物递归脱敏。
- **拒绝方案：** 只扩展 text 正则，或交给人工审阅发现。

### 争议 3：同仓 verifier 当前是否直接是 P0

- 治理初判 P0；可靠性反驳：当前 `release_passed` 固定失败且 publish job 禁用，所以尚未发生由同仓 verifier 直接放行生产。
- 治理接受边界，但指出任何未来 promotion 一旦信任它就成为 P0。
- **最终裁决：** 当前为 P1 治理缺陷；作为发布授权前必须修复，否则升 P0。唯一方案是外部受保护 verifier、独立 clean checkout、逐 blob 校验和固定 verifier digest。
- **拒绝方案：** 同一 PR 同时修改生产代码、生成器、验证器后给自己签 PASS。

### 争议 4：稀疏帧是否全部非法

- 测试破坏官要求拒绝“跳帧”；治理反驳：录制采样天然可能稀疏，所有不连续 frame index 都拒绝会误杀合法输入。
- **最终裁决：** step index 必须唯一顺序，时间必须单调有限；frame 引用必须真实。允许稀疏采样，但必须通过 `sampling_gaps` 明确原因和范围。
- **拒绝方案：** 不记录缺口；或无条件要求每一帧连续。

### 争议 5：`generated_at` 如何兼顾真实时间和确定性

- 可靠性指出当前时间进入内容会使重试 hash 漂移。
- “从内容 hash 派生时间”会伪造真实时间，也被拒绝。
- **最终裁决：** 服务端首次持久化记录真实 `created_at`，同一幂等键重试复用；canonical draft hash 不包含可变当前时间。审批凭证单独绑定账本时间和内容 hash。

### 争议 6：未跟踪工具目录是绕过还是噪声

- 运维指出 `.mimosa` 污染 fingerprint；测试破坏官反驳：当前 commit_bound 同时要求 clean 和 tracked，未跟踪文件不能静默变成通过。
- **最终裁决：** 当前为 P2 可重现性问题，不是已证实门禁绕过。tracked fingerprint 只覆盖 HEAD blob；未跟踪源另列并使 commit_bound 失败，不能无记录排除。

### 争议 7：路径和脱敏问题能否只靠设计消除

- 建设者组认为机制可由设计消除；破坏者组指出必须以 reparse/TOCTOU、逐指令崩溃、并发和嵌套秘密攻击验证，不能因文档增加条款就关闭。
- **最终裁决：** 设计条款是必要条件，不是关闭证据；完成实现、生成式攻击和故障注入前维持发布阻断。
