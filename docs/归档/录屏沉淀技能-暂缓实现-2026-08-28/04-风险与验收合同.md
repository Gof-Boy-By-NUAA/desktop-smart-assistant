# 录屏沉淀技能风险与验收合同

## 1. 合同作用

本合同定义未来启封、实现、发布和客户验收的最小边界。当前功能处于 `FROZEN_NOT_IMPLEMENTED`；以下条件不是待办建议，而是解除 VETO 的硬门禁。

## 2. P0 阻断风险

### P0-01：无完整用户闭环

当前只有独立 distiller 原型，没有录制、上传、分析、审阅、审批、安装和结果核验。解除条件：目标签名制品上的已认证员工能完成完整旅程，并看到失败、重试、取消、超时、断线恢复和 `IN_DOUBT`。

### P0-02：无服务端强制状态机和审批绑定

解除条件：owner-scoped FSM、attempt、幂等键、版本、墓碑、CAS、不可变副作用收据和审计账本全部实现；旧 attempt、非法跳步、撤销后重放、跨 owner、hash 不一致和重复安装均硬拒绝。

### P0-03：原始屏幕数据隐私不可撤回

生成后正则脱敏不能保护已经发给 provider 的原始像素。解除条件：明示同意绑定实际 provider/destination；外发前本地窗口/区域排除或遮挡；无法保护的敏感窗口失败关闭；所有产物、日志和错误递归脱敏。

### P0-04：发布信任链与客户制品不一致

解除条件：外部受保护 verifier 在独立 clean checkout 逐 blob 验证；固定依赖、Actions、镜像和工具；build once 生成签名 artifact、SBOM、provenance 和 verifier receipt；安装、迁移、soak、告警和客户只消费同一 artifact SHA。

### P0-05：目标客户与性能验收未执行

解除条件：同硬件、同数据、同负载的 SmartAssistant 配对基线证明现有能力非劣；每个改进模块以预注册指标和置信区间证明严格超越；目标客户在同一签名制品上执行真实旅程并签署绑定发布身份、环境和原始日志的验收包。

## 3. P1 高风险

| 编号 | 风险 | 解除条件 |
|---|---|---|
| P1-01 | IR 缺 provider/destination/frame/坐标/时序约束 | 严格版本化 allowlist、有限数、真实 frame、顺序 index、单调时间、边界 region 和显式 gap。 |
| P1-02 | 非 text 与未知嵌套字段泄漏敏感值 | 白名单序列化、全字符串递归脱敏、未知字段拒绝，三份产物及日志无原值。 |
| P1-03 | `write_draft` 路径逃逸和重解析点绕过 | 固定 owner 根、拒绝绝对/UNC/设备/reparse、TOCTOU 攻击测试通过。 |
| P1-04 | 逐文件写和崩溃留下半成品 | 同卷 staging、文件/目录 fsync、原子 rename、READY、恢复与并发测试通过。 |
| P1-05 | 当前时间导致 draft hash 不稳定 | 首次账本时间按幂等键复用，canonical 内容不含可变当前时间，同输入同 hash。 |
| P1-06 | NaN/Infinity/非法覆盖值产生非业务异常 | 写入前有限数校验、`allow_nan=False`、统一失败且零副作用。 |
| P1-07 | 同仓 generator/verifier 自证 | 外部受保护 verifier 和独立信任根；仓库报告仅诊断。 |
| P1-08 | commit_bound 可被特殊 index 标记隐藏 | 逐 blob 对比 HEAD，拒绝 assume-unchanged、skip-worktree 和未跟踪源。 |
| P1-09 | 发布工作流漏专项门禁或缺制品仍成功 | 受保护 screen-skill gate；缺专项报告/E2E/任一平台制品即失败。 |
| P1-10 | 任意 overlay ref 接触长期生产秘密 | 仅允许审核完整 SHA，短期最小权限 token 和受保护环境审批。 |
| P1-11 | 升级无迁移事务和自动回滚 | N-1→N→N-1、逐边界中断、健康失败自动回滚实机证明。 |
| P1-12 | 容器与监控生产断层 | 固定 digest、最小权限、TLS/认证、healthcheck、资源/网络限制、72h 与告警回执。 |

## 6. 性能验收合同

### 6.1 原能力非劣

- 冻结 SmartAssistant 基线和候选 R 的可执行版本及制品摘要。
- 使用同一机器、同一数据副本、同一任务顺序随机化和相同预热规则。
- 报告逐样本成功率、端到端延迟、CPU、峰值 RSS、磁盘和外部调用成本。
- 成功率不得下降；延迟和资源按预注册非劣界值判断，不能只比较均值。

### 6.2 改进模块严格超越

- 每个模块在运行前登记主指标、方向、样本量、排除规则、随机种子和置信区间方法。
- 保存配对原始样本和异常明细；不能只保存聚合值或截图。
- “超越”要求主指标的置信区间整体越过预注册改善阈值，不能用点估计或单次最好结果。
- Knowledge/检索、Memory、Skills 和录屏分别声明，不能用一个模块的提升抵消另一个模块退化。

### 6.3 录屏专项

- 分层覆盖办公软件、浏览器、多显示器、DPI 缩放、权限拒绝、模型失败、长流程和敏感窗口。
- 预注册人工盲审标准；“IR 可直接落地率”不低于 80%，同时报告样本量、分层、评审一致性和置信区间。
- Win10、8 GiB RAM、SSD 实机测量额外 CPU 负载目标低于 5%，并报告内存、磁盘和 UI 卡顿。

## 7. 客户验收合同

客户验收包必须包含：customer/case ID、执行人、时间、环境、R commit/tree、artifact SHA、SBOM/provenance 摘要、配置与 provider、数据集/录制任务哈希、逐步骤结果、日志、失败明细、客户判定、客户签名和外部 verifier receipt。

至少执行：登录与权限、开始/停止录制、上传、取消、断线恢复、provider 不可用、敏感窗口保护、IR 审阅修正、审批、hash 变化拒绝、安装、技能列表核验、删除/TTL、重启恢复和跨 owner 拒绝。

## 8. 硬否认防篡改测试

未来启封后，测试破坏官必须反复尝试：手改 JSON、复制旧报告、替换 generator/verifier、隐藏 Git 修改、删除报告、把缺失字段写为 `N/A/PASS`、验收后重建制品、签名不同摘要、伪造客户字段。任何路径若能使 release promotion 成功，保持 VETO。
