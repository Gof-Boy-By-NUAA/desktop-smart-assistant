# 外部技能演化能力评估

## 本节点结论

附件描述的方向可分阶段实现，但不能一次性命名为 AutoSkill、EvoSkill、MemSkill、
CoEvoSkills 或 SE-Agent。当前安全加入的是“受治理工作手册”的读取侧和候选侧基础设施：

1. active-only 词法 Top-K 检索与默认关闭的生产注入；
2. 结构化候选包含适用条件、步骤、验证规则、禁用条件、模型兼容和来源；
3. 已完成影子证据可触发后台复盘中的 `skill_propose`，候选保持 inactive；
4. 遥测 schema v2 与演化证据消费者的契约已恢复，并有真实导出集成测试。

这仍不是自动演化闭环。候选不会自动验证、合并、发布或进入提示词。

## 能力边界

| 附件能力 | 当前状态 | 决策 |
|---|---|---|
| AutoSkill 检索 | 仅租户化词法检索，不是向量加 BM25 | 保持默认关闭，等待真实技能金标 |
| EvoSkill 失败提案 | 有证据约束的 inactive 候选提案 | 保留；不得自动发布 |
| Add / Merge / Discard | 只有 propose/reject/publish 治理原语 | 不添加自动决策器 |
| CoEvoSkills | 有固定配对套件和客户 Oracle 框架 | 等待真实客户包和独立 Judge |
| MemSkill | 有记忆检索、写入、撤销和回滚工具 | 不添加训练式 Controller 或奖励学习 |
| SE-Agent | 没有同任务多轨迹隔离、评分和副作用合并 | 不在当前架构上直接添加 |

## 暂不添加的原因

当前技能选择文件不是可用金标：30 条记录没有完整 REST 来源证明，21 个正标签由标题关键词
直接生成，且存在快照时间早于记录更新时间的矛盾。因此无法以真实指标证明自动选择、自动
合并或记忆操作策略改善任务成功率。此时加入自动写入或自动发布只会扩大不可验证行为面。

手工“记忆操作 Skill”也不在本节点直接发布。它可以在客户提供固定长对话场景、期望记忆
操作、禁止操作和成功判据后作为 inactive 候选进入同模型配对评测；通过治理发布门禁后，
才能申请小流量启用。当前不能把静态提示词候选描述为 MemSkill。

## Knowledge 到候选 Skill 的后续边界

代码级评估确认，可以在后续节点增加“已验证 Knowledge 引用 -> 受治理 inactive 候选
Skill”的窄桥接，但当前不直接加入。只有 `SHARED` 且敏感度为 `PUBLIC` 或 `INTERNAL`
的 active 引用可以作为来源；调用身份必须同时具备 Knowledge 读取权和 `skill:propose`。
提案必须保留引用 URI、UTF-8 字节范围、正文哈希和引用哈希，并且只能调用现有
`GovernedSkillService.propose()` 创建 `CANDIDATE`。

暂缓实现的直接原因不是生成能力，而是 Knowledge 与 Skill 使用两个 SQLite 事实库，现有
事务不能原子覆盖“来源复核 -> 候选落库”。发布门禁也尚未再次核验 Knowledge 来源是否仍
active，无法关闭跨进程撤销竞态。在补齐二次事实回查、发布时来源复核和权限负向测试前，
不能把 Memory/Knowledge 自动晋升为 Skill，更不能自动评测或发布。
