# 受控客户技能验收框架

## 评估结论

附件描述的“外部工作手册”方向可以在 SmartAssistant 上分阶段实现。当前可安全批准的范围是
评测专用受控技能注入和客户配对验收。代码中已有独立开关控制的生产 Top-K 提示词注入
路径，但默认关闭且尚未通过本框架的真实客户验收；它不等于已获准上线。未经客户数据
验证的自动新增、合并、淘汰或记忆控制器训练仍不批准。

评估输入 SHA-256：

```text
3885CEC065BF67CF89DFDAB42633D71BF87CB43BD60C334D656CE42900EC690A
```

当前实现对应 AutoSkill 的结构化技能资产、EvoSkill 的候选治理和 CoEvoSkills 的 Oracle 门禁思想。MemSkill 的奖励训练控制器、SE-Agent 的多轨迹融合以及自动 `Add / Merge / Discard` 尚无客户指标和安全证据，因此没有进入生产路径。

## 实现边界

新增模块位于 `benchmarks/customer/`。生产智能体循环(Agent Loop)和提示词构建器不会
自动调用该验收框架，技能发布状态机也不会因验收命令自动发布候选。

```text
客户 manifest.json + cases 文件
  -> 严格结构、路径、数量、候选版本和 SHA-256 校验
  -> 从治理事实库读取指定租户、版本和正文哈希的 candidate/active 技能
  -> baseline 臂不注入技能
  -> candidate 臂只向评测执行请求注入一个结构化技能
  -> 执行器 Ed25519 签名完整请求、输出、令牌、延迟和制品
  -> 确定性 Oracle 或签名的独立客户 Judge 判定输出
  -> 配对指标、Bootstrap 95% 置信区间和门禁
  -> 追加事件哈希链
  -> verify.py 从客户包和逐事件记录独立重算
```

评测过程不写技能目录、不发布技能、不修改治理配置。候选执行前后及整轮结束都会回查治理状态和正文哈希；状态变化立即失败关闭(Fail Closed)。

## 客户包和执行边界

- 清单拒绝未知字段、重复 JSON 键、NaN、路径越界、符号链接和 Windows 重解析点；根目录的已有父路径组件也会检查。
- 清单固定租户、模型标识、模型参数、脱敏端点哈希、基础提示词哈希、工具哈希、Oracle、完整场景数量、候选技能 ID/版本/正文哈希、执行器/判定器制品哈希和 Ed25519 公钥、允许/禁止技能及验收阈值。
- 预期技能正文必须是严格 64 位 SHA-256 十六进制，并与治理事实库复核。
- 子进程执行器使用固定字符串数组、`shell=False`、单臂独立临时工作区、父路径重解析点检查、超时和响应大小限制。
- 执行器必须回传环境快照和完整请求哈希；请求哈希覆盖场景输入、臂和实际技能载荷，两臂的模型环境快照必须相同。
- 执行器用客户包固定的 Ed25519 私钥对应公钥，对请求哈希、输出哈希、令牌数、内部执行延迟和执行器制品哈希签名；报告生成器无法只靠重算 SHA-256 链伪造这些观察值。
- 基线/候选顺序由场景哈希确定性交错，降低固定顺序偏差。

## 判定、证据和门禁

执行器返回输出、令牌数、内部延迟、环境快照、完整请求回执和签名，不能自报正确。确定性任务使用内置规范 JSON Oracle；客户自然语言任务必须提供与 Agent 执行器分离并具有客户包固定公钥的签名 Judge。

逐事件证据记录输出哈希和 Oracle 证据哈希，不保存客户原始输出。事件链为：

```text
run.started -> 2 * case.executed -> run.finished
```

独立验证器不调用运行器的指标聚合函数，会检查事件顺序、场景完整性、治理正文哈希、固定候选、基线技能泄漏、候选注入一致性、完整请求回执、执行器/判定器 Ed25519 签名、执行环境、盲化标签、确定性 Oracle、指标、门禁和最终状态。即使攻击者重算普通事件哈希链，没有客户包对应私钥也不能生成可通过验证的新观察值。

门禁包括：完整客户场景、成功率严格提升、配对 Bootstrap 95% 置信区间下界大于零、最大回归数、关键场景零回归、P95 延迟比和总令牌预算。

## 缺输入状态

没有真实客户包、执行适配器、客户 Judge 或客户签署结果时，命令行只输出：

```json
{
  "schema_version": 1,
  "status": "pending_customer_inputs",
  "passed": false
}
```

退出码为 `2`。这条状态不能进入通过或发布路径。

## 修复影响分析(Fix Impact Analysis)

- 新代码只位于 `benchmarks/customer/`、测试和工作流，不改变生产 Agent Loop、提示词或工具调用接口。
- 治理技能数据库只读；现有提案、验证、发布和回滚状态机未改变。
- 客户包是新的严格 schema，没有旧版兼容负担；未来字段变化必须提升 `schema_version`。
- 独立验证器绑定客户验收全部可执行模块及共用路径安全代码的实现指纹，旧报告在实现变化后需要对应源码版本才能复核。
- 普通事件链仍没有第三方时间戳；真实性来自客户包固定的执行器/判定器公钥和制品哈希。客户必须通过报告生成者之外的渠道确认清单 SHA-256 与公钥，否则生产者仍可替换整个客户包。
- Ed25519 签名证明观察值来自对应私钥持有方，不证明私钥持有方的实现本身正确；执行器和客户 Judge 仍需由客户控制或独立审计。
- 签名能力依赖可选依赖 `cryptography>=41.0`，技能持续集成(CI)工作流会显式安装。

## 启用生产功能前的门禁

1. 客户提供完整场景包、固定候选、模型、提示词、工具、端点、制品和公钥指纹，并从独立渠道确认清单 SHA-256。
2. 接入由客户或独立环境持有私钥的真实执行适配器；自然语言验收还需签名的独立客户 Judge。
3. 在完整客户集上由独立验证器复算，且客户确认报告和原始证据保管方式。
4. 通过后再单独评审生产技能检索与提示词注入；当前不能自动开启。
5. 自动新增、合并、淘汰、MemSkill 控制器或多轨迹融合必须各自进行消融实验(Ablation Study)和回归门禁。
