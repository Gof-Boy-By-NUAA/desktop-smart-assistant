# 安全威胁模型

## 适用边界

当前 SmartAssistant 桌面运行时按“可信设备上的单个本地用户”设计。记忆与知识
生命周期工具中的身份、范围和敏感级别检查，是应用层授权边界；它们不能替代操作
系统进程隔离。

以下场景在当前边界内：

- 同一台可信设备上的单用户桌面会话；
- 普通 Agent 通过 `memory_*`、`knowledge_*` 工具访问治理数据；
- 通用 `read`、`ls`、`search_files` 和 `memory_get` 对机器管理目录的误访问拦截；
- 受信任管理员备份、恢复或迁移本地工作区。

以下场景不在当前边界内：

- 互不信任的多个租户共享同一个操作系统账号或 SmartAssistant 进程；
- 恶意本地用户、恶意插件或已经获得任意命令执行能力的攻击者；
- 操作系统账号、模型供应商或管理员凭据已经失陷；
- 把命令字符串正则当作文件系统沙箱。

## Bash 不是授权边界

`bash` 工具以 SmartAssistant 进程的操作系统权限执行命令。命令可以通过变量、脚本、
符号链接、编码或子进程动态构造路径，因此任何命令字符串匹配都只能减少误操作，
不能保证机密性。

2026-07-29 的可复现实验在临时工作区创建
`knowledge/.system/secret.txt`，随后用字符码动态构造路径。命令文本不包含
`knowledge`，但仍读出 canary：

```text
{'status': 'success', 'canary_exposed': True, 'command_contains_literal': False}
```

因此：

- 无人值守的后台 Evolution 不得获得 `bash`；
- 通用文件工具的路径拦截不得描述为可抵御任意代码执行；
- 交互式 `bash` 只在可信本机单用户模式保留，用于维持 SmartAssistant 原有工程能力；
- 多租户或不可信输入部署必须按租户使用不同操作系统身份、容器或等效文件系统
  沙箱，并把知识数据库和密钥排除在命令进程可读范围之外；无法提供该隔离时必须
  禁用 `bash`、外部脚本和可执行插件。

## 数据静态保护

治理事实源当前是本地 SQLite 文件。应用工具会阻止普通读取，但拥有同一操作系统
账号文件权限的进程仍可读取数据库。磁盘加密、独立服务账号、备份访问控制和密钥
管理属于部署责任。不得把当前实现宣传为对本机管理员或任意代码执行的加密保护。

## 验收门禁

- 应用层：跨租户、跨用户、跨会话、受限级别和撤销后污染率必须为零；
- 派生数据：事实源、检索索引和兼容投影必须可重建并通过完整性核验；
- 后台 Agent：工具集合必须采用明确允许列表，且不得动态重新注入被移除的工具；
- 多租户部署：必须额外提供操作系统级隔离测试，不能用应用层单元测试替代；
- 安全结论必须附可复现命令、日志或攻击用例，不接受仅依赖提示词的声明。
