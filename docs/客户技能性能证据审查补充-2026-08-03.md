# 客户技能性能证据审查补充（2026-08-03）

## 范围与结论

审查客户技能、性能验收及 release 绑定，不重新判定既有 Web 执行账本。
五个启用角色完成三轮审查后均投 VETO。本次只收紧本地合同；没有外部客户、
受保护 CI、签名制品或生产验证，不能解除任何发布或客户硬否认。

| 角色 | 决定 | 可验证 VETO 条件 | 拒绝方案 |

| 测试破坏官 | VETO | 黑盒 conformance suite 覆盖篡改、崩溃、取消、重放、部分输出和并发压力。 | 正常夹具通过即称安全。 |
| 运维与部署审计官 | VETO | 构建、制品签名、安装/回滚、长稳、告警和生产策略均有同 commit 证据。 | 将开发机 pytest 当部署验证。 |

## Local v2 follow-up (2026-08-03; not an approval)

The local contract now rejects equal release fields across the two arms,
environment-descriptor hash tampering, wrong observed release identities,
re-signed candidate-to-baseline receipt swaps, trust-key purpose reuse,
baseline-artifact evidence claims, and altered release signatures. These are
local fail-closed tests only. The five VETOs remain effective: no external
customer execution, protected CI, deployment, provider/OS receipt, or customer
signature evidence exists.

The subsequent local revision additionally binds external evidence to report
run_id and event-chain head, rejects cloned canonical case inputs, and keeps
customer/Skills production denials unchanged even when a local caller supplies
a structurally valid trust root and signed evidence through environment
variables. This closes a local self-attestation bypass; it does not supply the
missing protected external verifier, artifact launcher, independent resource
metering, deployment evidence, or formal customer acceptance.
