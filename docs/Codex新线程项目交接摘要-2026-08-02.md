## 0. 本轮续作更新（2026-08-02，优先阅读）

### 本轮完成的本地修复

- **桌面端 SSE 终态与恢复**：`desktop/src/renderer/src/store/chatStore.ts` 不再把 `EventSource.onerror` 直接标记为完成；每次重连均重新申请 owner/request-bound、one-shot ticket，最多 3 次指数退避。重试耗尽后保留 `requestId` 和 Stop 操作，显示 `isStreamInterrupted` / “结果尚未确认”，而不是伪造成功或已取消。
- **取消闭环**：`POST /cancel` 的 `success` 只表示取消信号已送达。桌面端继续监听，直到 SSE `cancelled` 与最终 `done`；不再提前关闭流、清空 requestId 或显示最终 cancelled。
- **SSE 事件重放**：`channel/web/web_channel.py` 的生产 SSE 队列已改为有界 `_SSEEventJournal`，输出单调 `id:`；ticket 绑定 `after_event_id`，重连从最后确认事件之后重放。新生成器会 fencing 旧生成器，旧连接不能清理新连接的 journal。日志容量耗尽会发送明确的 `error/unconfirmed`，不会静默丢事件。
- **新文件 URL 去 bearer 化（局部）**：上传、SSE `file_to_send`、artifact、workspace raw URL 与 ASR/TTS 音频现在由 `channel/web/web_channel.py:_encode_file_capability` 生成 `/file/<capability>`。capability 绑定规范绝对路径和 owner、HMAC 防篡改、默认 300 秒且最大 600 秒；桌面端对 `/file/` 不再附加长期 bearer。新增 capability 篡改/过期/owner-path 绑定测试。
- **防回归测试**：新增 `tests/test_web_sse_replay.py`（游标重放、连接接管、ticket owner/request/cursor 一次性绑定、容量溢出显式失败）；`tests/test_deployment_contract.py` 加入桌面 ticket/cursor/reconnect 契约。

### 当前最高优先级未关闭项

1. SSE journal/ticket 仍是**进程内**状态：进程重启/多实例故障转移不能恢复；需要 durable run/event journal 与部署级共享存储，才能关闭可靠性 VETO。
2. 新输出已使用短 TTL 单文件 capability，但历史消息重建和若干 legacy `/api/file`/`/uploads` 兼容路径仍可能通过 bearer query；还缺 capability logout-revocation、单用途下载策略和历史迁移，不能宣布该风险关闭。
3. Scheduler 虽已补 owner、锁、原子写和损坏 fail-closed，仍没有跨重启 execution lease / outbox / exactly-once 副作用证明。
4. Agent 工具副作用、memory/evolution 写入仍缺 durable run journal、CAS/事务性恢复。
5. 任何本地 PASS 均不能替代 customer acceptance、签名发布制品、受保护 Git/远程独立 verifier、部署/回滚/72H/告警证据。

#### Web 安全/会话/身份

- 会话增加 owner/state、认领、所有权校验、墓碑删除和迟到写入阻断。
- Bearer token 使用带版本/iat/exp/nonce/HMAC 的 v3 形态；密码轮换、注销、重启可失效旧 token；冲突认证凭据 fail-closed。
- 默认 Web 绑定强制 loopback；公网访问要求 TLS reverse proxy，Host/Origin 做 DNS rebinding 防护。
- Web cancel、session delete、scheduler context 注入均增加 owner 约束；登录失败增加限流。
- 上传/ASR/TTS/`/api/file`/workspace resolve 做 owner 根隔离；filesystem root serve 被拒绝。
- Citation 使用签名 session binding、TTL、scope 和 tombstone；删除会话后 citation 返回 410。
- SSE 不再接受 `token` bearer query；改用短 TTL、request-bound、one-shot stream ticket。

当前 Web boundary security：26 项攻击检查通过；独立 verifier 7 项检查通过，但报告明确标记为 local-only，不能代替生产/客户执行。

#### 桌面端交付闭环与 UX

- multipart upload/import/ASR 统一使用 authenticated fetch，错误信息可见。
- 取消操作改为“两阶段”：后端/SSE 确认前不显示最终 cancelled。
- 登录失败 fail-closed；新增 logout，清理 token、会话和流。
- session/history/knowledge 的加载失败增加 retry/error 状态，删除/重命名/清空有确认或错误反馈。
- 新增只读 `DeliveryPage`，展示 manifest、formal gates、reports、hard denials；没有本地写 PASS 的接口。
- 新增后端只读 `/api/release/evidence`，读取并独立校验 manifest；缺失/无效证据返回阻断。

#### CI/发布契约

- `.github/workflows/release.yml` 已加入 release-preflight，构建 job 依赖 preflight，并运行 selected tests 与 manifest verify。
- Web/Knowledge/Retrieval 的报告与独立 verifier 均有 CI workflow 和 artifact 上传路径。
- Web 相关文档当前要求 loopback + TLS reverse proxy，不能直接把 HTTP 暴露到公网。

### 5.2 已知产品/可靠性风险，尚未关闭

1. SSE ticket 是进程内状态；进程重启/故障转移丢 ticket。一次性消费可防 replay，但被盗 ticket 先消费会造成 DoS；桌面端还没有完整的有限重连、历史恢复和 `unconfirmed` 状态。
2. 非 SSE 图片/文件 URL 仍有 bearer query 兼容路径，尚未全部改成短 TTL capability/blob fetch。
3. subject token 的长期持久化 owner capability、cloud callback 身份绑定、远程 Skill 签名/allowlist、bash/background owner 隔离仍需继续审查/修复。
4. scheduler 仍需跨进程锁、atomic storage、损坏 fail-closed、lease/execution_id、退避/死信和 owner-scoped 操作的正式压力/故障测试。
5. 同 session 并发、session clear/delete 与在途任务、工具副作用与消息落库之间仍需单飞锁、generation fencing、durable run journal/idempotency。
6. memory/evolution/file write 存在原子提交、CAS、迁移原子性、恢复混合版本等可靠性风险。
7. 生产构建、Docker、安装器、签名、公证、回滚、密钥权限、72h soak、生产告警均尚未真实执行。

1. 全量回归、桌面构建、Docker/安装器 smoke、迁移/回滚、72h soak 和告警 fire test 有可复核结果。
2. 所有改进模块在固定数据/协议/环境下相对 SmartAssistant 基线达到合同阈值，并可由独立 verifier 重算。
3. 证据绑定受保护 commit/tree、签名制品 digest 和外部 verifier attestation。
4. 客户真实执行并签署 acceptance package。
5. 五角色第三轮没有 VETO，所有 APPROVE_WITH_AMENDMENT 条款已写入合同并验证。

在此之前，最终状态必须保持 **未完成/不可发布**。
