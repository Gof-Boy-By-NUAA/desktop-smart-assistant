## 已确认根因与修改

1. **CONFIRMED：模型目录主要来自静态推荐表。** 已有自定义模型保存能力不能说明发现流程可用。`models/catalog.py` 为已有官方枚举协议增加适配，`web_channel.py`、`client.ts`、`CapabilityCard.tsx` 和 `console.js` 接入目录；模型 ID 不作为后端授权白名单，未知能力保持 UNKNOWN。发现失败保留推荐项和自定义入口，并明确提示失败。
2. **CONFIRMED：目录业务错误未可靠进入 renderer 错误路径。** HTTP 200 的 `status=error`、provider 不匹配及无效模型数组现在被拒绝；Web 页面也显示失败状态。修复前客户端定向测试 2 FAIL / 1 PASS；修复后全部通过。
3. **CONFIRMED：GLM-5.3 系列的思考参数与文档约束冲突。** Agent 在关闭深度思考时传 `thinking=disabled`。`zhipuai_bot.py` 仅对精确型号 `glm-5.3`、`glm-5.3-flash`、`glm-5.3-flashx` 转为 `enabled` + `low`；保留用户显式开启时的 effort，旧型号与未知自定义型号不套用该规则。修复前参数测试失败，修复后通过，正式包真实 SDK 发出的流式请求也已核对。
4. **CONFIRMED：推荐项需维护。** `common/const.py` 与后端推荐表补充上述三项，保留 GLM-5.2；移除官方标记退役的 Kimi 推荐项，不禁止保存或使用自定义 ID。桌面界面说明模型的思考模式与账号/API 地址限制。

原用户环境中 GLM-5.2 实际调用失败的唯一根因仍 **UNKNOWN**，没有该环境的真实 API 错误证据。不能把上述确认问题等同于其全部原因。
