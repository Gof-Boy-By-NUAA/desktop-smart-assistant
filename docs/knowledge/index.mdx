The personal knowledge base is the Agent's governed long-term structured knowledge store. SQLite is the source of truth; the workspace `knowledge/` directory is a generated, read-only compatibility projection. Unlike timeline-oriented memory, knowledge is organized by topic and versioned with scope, provenance declarations, audit records, and revocation.

## Core Concepts

### Knowledge vs Memory

| Dimension | Knowledge Base (knowledge/) | Long-term Memory (memory/) |
| --- | --- | --- |
| Organization | By topic, interlinked | By timeline, dated files |
| Writing | Agent actively structures content | Auto-summarized on context trimming |
| Content | Refined, structured knowledge | Raw conversation summaries |
| Use cases | Study notes, tech docs, project knowledge | Conversation history, event records |

### Read-only Projection

```
~/cow/knowledge/
├── index.md          # Generated knowledge index
├── log.md            # Generated lifecycle log
├── concepts/         # Conceptual knowledge
│   └── machine-learning.md
├── entities/         # Entity knowledge (people, orgs, tools)
│   └── openai.md
└── sources/          # Source knowledge (articles, papers)
    └── llm-wiki.md
```

The projection structure is flexible, but it must not be edited with generic file or shell tools. Creation and updates use `knowledge_write`; prior versions and removal use `knowledge_rollback` and `knowledge_revoke`.

## Automatic Organization

Knowledge writing is an autonomous Agent behavior, triggered in these scenarios:

- **User shares an article or document** — The Agent automatically extracts key information and creates a structured knowledge page
- **Conversation produces valuable conclusions** — The Agent organizes insights into knowledge pages and links them to existing knowledge
- **User explicitly requests organization** — Users can guide the Agent to organize and update knowledge through conversation

Each knowledge page includes cross-reference links to related pages, gradually building a knowledge graph.

## Knowledge Retrieval

The Agent retrieves governed knowledge during conversation through:

- **Governed search** — `knowledge_search` applies tenant, user, session, collection, and sensitivity filters
- **Verified read** — `knowledge_get` accepts the complete Citation v3 URI returned by search
- **Citation v3** — Each `knowledge://` URI binds the immutable version, evidence byte range, content hash, quote hash, and `source_ref_hash`

Citation URIs must be preserved verbatim. Never shorten, reorder, or reconstruct one. When a citation is updated, revoked, or from an unsupported version, search again. `source_ref_hash` proves that the stored source declaration has not changed; it does not independently prove that an external source is authentic.

## Web Console

The web console provides a dedicated "Knowledge" module with:

- **Document browsing** — Tree-style directory structure, searchable and collapsible, click to view content
- **Knowledge graph** — Interactive graph visualizing relationships between knowledge pages
- **Chat integration** — Projected Markdown document links can navigate to the document browser. Verified `knowledge://` citation resolution is performed through the governed tools.

## CLI Commands

Manage the knowledge base with the `/knowledge` command:

| Command | Description |
| --- | --- |
| `/knowledge` | Show knowledge base statistics |
| `/knowledge list` | Display file directory as a tree |
| `/knowledge on` | Enable the knowledge base feature |
| `/knowledge off` | Disable the knowledge base feature |

## Configuration

| Parameter | Description | Default |
| --- | --- | --- |
| `knowledge` | Whether to enable the personal knowledge base | `true` |
| `agent_workspace` | Workspace path containing the generated `knowledge/` projection | `~/cow` |
